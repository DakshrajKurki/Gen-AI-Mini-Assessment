# Local GitHub Repository Code Explainer

**RepoLens AI** is a GenAI web application that takes a public GitHub repository URL and explains the project in simple language. The explanation is written by a small open-source LLM (Qwen 2.5, 0.5B) from the repository's real files. Nothing is hard-coded.

---

## 1. Project Overview

Paste a URL such as `https://github.com/psf/requests`. The app clones the repository, finds the important files, builds a compact text summary of them, and asks an LLM to explain what the project does, how it is organised, and which technologies it uses. The result is shown in a Streamlit interface.

## 2. Problem Statement

Opening an unfamiliar repository is slow. A newcomer has to find the README, guess the entry point, and read several files before understanding what the project does. This is especially hard for students working with open-source code.

## 3. Objective

Build a working GenAI application that automates this first read-through:
**GitHub Repository → Code Processing → LLM → Backend → Frontend → Explanation.**

## 4. Features

- Validates the URL (accepts repository URLs, rejects file, folder and non-GitHub links)
- Shallow-clones the repository into a temporary folder and always deletes it afterwards
- Ignores junk (`.git`, `node_modules`, `venv`, `dist`, tests, lock files, binaries, huge files)
- Prioritises README, config files (`requirements.txt`, `package.json`, ...), entry points, then central source files
- Strict limits on files and characters, so even a 0.5B model gets a context it can handle
- Explanation generated by an LLM in seven sections (overview, features, structure, workflow, technologies, code components, summary)
- Runs locally with **Ollama** and online with **Hugging Face Transformers**, using the same model family
- FastAPI backend (`/explain`, `/health`) that reuses the same modules
- Friendly error messages. Users never see a stack trace.

## 5. Architecture

```
GitHub Repository
       ↓
Repository Cloning        (backend/repository.py, GitPython)
       ↓
Code Processing           (backend/code_processor.py)
       ↓
Repository Context        (structure + README + config + code snippets)
       ↓
Qwen 2.5 0.5B             (backend/llm.py)
   ├─ local : Ollama  qwen2.5:0.5b
   └─ online: Hugging Face  Qwen/Qwen2.5-0.5B-Instruct
       ↓
Generated Explanation
       ↓
Streamlit UI              (frontend/app.py)
```

Two ways to use the same pipeline:

```
Streamlit (frontend/app.py) ──imports directly──►  repository → code_processor → llm
FastAPI   (backend/main.py) ──imports directly──►  repository → code_processor → llm
```

Streamlit does **not** call FastAPI. That is why the app works on Streamlit Cloud, where no separate server is running.

## 8. How It Works

1. **Validate**: `urllib.parse` checks the host is github.com and the path is exactly `owner/repo`.
2. **Clone**: GitPython runs a shallow clone (`depth=1`) into a temp folder.
3. **Scan**: the walker skips ignored folders, tests, lock files, binaries and files over 300 KB.
4. **Select**: files are scored (README > config > entry points > central source) and the top ones are chosen, up to 10 files and about 8,000 characters in total.
5. **Context**: directory tree, language counts, dependencies, README and code snippets are joined into one text block.
6. **Prompt**: a system prompt ("You are a software project explainer ...") plus the context and the seven required headings.
7. **Generate**: Ollama is used if it is running, otherwise Hugging Face Transformers.
8. **Display**: Streamlit shows the explanation and the repository details. The temp clone is deleted in a `finally` block.

## 9. Local Installation

**Windows (Command Prompt or PowerShell)**

```bat
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

**macOS / Linux**

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Git must also be installed (`git --version`). Get it from https://git-scm.com if it is missing.

## 10. Ollama Setup

1. Install Ollama from https://ollama.com/download
2. Pull the model (about 400 MB):
   ```
   ollama pull qwen2.5:0.5b
   ```
3. Make sure Ollama is running. The desktop app starts it automatically, or run `ollama serve`.
4. Check it: open http://localhost:11434 and you should see "Ollama is running".

If Ollama is not running, the app automatically falls back to Hugging Face. The first fallback run downloads the model (about 1 GB).

## 11. Running the Application

**Streamlit app** (the main interface), from the project folder:

```
python -m streamlit run frontend/app.py
```
or double-click `run_frontend.bat`. Open http://localhost:8501

**FastAPI backend** (optional, for demonstrating the API):

```
uvicorn backend.main:app --reload
```
or double-click `run_backend.bat`. Open http://127.0.0.1:8000/docs and try `POST /explain` with:

```json
{ "repo_url": "https://github.com/psf/requests" }
```

Optional settings (environment variables): `OLLAMA_URL`, `OLLAMA_MODEL`, `LLM_BACKEND` (`auto`, `ollama` or `huggingface`), `HF_DTYPE` (`bfloat16` or `float32`).

## 12. Streamlit Cloud Deployment

1. Push the project to a **public GitHub repository** (see the git commands below). The repository root must contain `backend/`, `frontend/`, `requirements.txt`.
2. Go to https://share.streamlit.io and sign in with GitHub.
3. Click **Create app** and choose your repository.
4. Set **Branch** to `main` and **Main file path** to `frontend/app.py`.
5. Under **Advanced settings**, pick **Python 3.11** (the PyTorch wheels are best supported there).
6. Click **Deploy**. The first build installs PyTorch and takes several minutes.

On the cloud there is no Ollama, so the app uses Qwen/Qwen2.5-0.5B-Instruct through Transformers. The first analysis downloads the model and is slow. After that the model stays cached in memory (`st.cache_resource`) until the app restarts. The free tier has limited CPU and RAM, so expect a response in roughly a minute or more and use small repositories for the demo.

```
git init
git add .
git commit -m "RepoLens AI - GitHub repository code explainer"
git branch -M main
git remote add origin https://github.com/<your-username>/github-code-explainer.git
git push -u origin main
```

## 13. Example Usage

Input: `https://github.com/psf/requests`

The app clones the repository, selects README.md, `pyproject.toml` and core source files such as `api.py`, `adapters.py` and `auth.py`, and the model returns sections like:

- **Project Overview**: Requests is a Python library that makes HTTP requests simple.
- **Technologies Used**: Python, with urllib3, certifi, idna and charset_normalizer.
- **Simple Summary**: a short plain-language recap.

The exact wording differs on every run because it is written by the LLM.

## 14. Limitations

- A 0.5B model is small. It can miss details, repeat itself or occasionally get something wrong. Always check important facts against the code.
- Only a limited slice of the repository (about 8,000 characters from at most 10 files) is read, so large projects are explained from their README, config and most central files.
- Only public GitHub repositories are supported. Private repositories and other hosts are rejected.
- Repositories over 300 MB are rejected.
- Cloud inference runs on a shared CPU, so it is slow.
- Only Python, JavaScript/TypeScript, Java, C/C++, C#, Go, Rust, PHP, HTML, CSS and SQL source files are analysed.

## 15. Future Enhancements
